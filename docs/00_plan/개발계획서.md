## 2. OEM 확인 필요 사항과 잠정 가정

> 1단계에서 Q-07~Q-10이 추가됐다. 최신 목록은 `docs/01_requirements/SWR-004_OEM질의및검토기록.md`를 따른다.

| ID | 내용 | 잠정 가정 |
|---|---|---|
| Q-01 | 출력 결정 우선순위가 정의되지 않음 (SR-001/002/004, FR-002/005/006/007 상충) | 아래 표의 우선순위 적용 |
| Q-02 | FR-003(QM) 재입력 override가 SR-002(ASIL B) 해제 억제를 무력화할 수 있음 | override는 경고·이유코드만 생성하고, 접근위험이 TRUE인 동안 출력은 LOCK 유지 (ASIL B 우선) |
| Q-03 | 평가 주기 값이 없음 | 50 ms 주기로 가정. 300 ms(SR-001), 100 ms(SR-003) 기준을 주기 수로 판정 |
| Q-04 | crash_status = PENDING 동작 미정의 | PENDING은 출력 변경 없음, 이유코드 `CRASH_PENDING`만 기록 |
| Q-05 | 4절은 음성·모바일 앱 제어를 주장하지 말라고 하나 FR-001/IF-004는 해당 경로를 요구 | FR-001/IF-004를 따름(네 경로 모두 처리). 4절은 Tesla 참고 해석에 대한 제한으로 해석 |
| Q-06 | 9절 추적표에 SWR-019 없음 | SWR-019는 결번 처리하지 않고 1단계에서 필요 시 사용, 결번이면 사유 기록 |

**잠정 출력 우선순위 (Q-01)** — 위가 우선

1. ignition_on = FALSE → 양쪽 RELEASE, 상태 OFF (FR-007)
2. crash_status = CONFIRMED → 양쪽 RELEASE (SR-001)
3. sensor_fault = TRUE → 직전 확정 출력 유지, 상태 FAULT (SR-004)
4. 입력 무효/지연 → 상태 DEGRADED (SR-003), 출력은 직전 값 유지
5. 화재·과온·성인 탑승 → 양쪽 RELEASE (FR-005)
6. 후측방 접근위험 → 해당 도어 LOCK, 해제 억제 (SR-002)
7. ISOFIX 연결 → 해당 도어 LOCK (FR-006)
8. 차속 ≥ 3 km/h → 양쪽 LOCK (FR-002)
9. 운전자 명령 (FR-001)

> 2(충돌)를 1(시동 OFF)보다 아래에 둔 것은 두 경우 모두 RELEASE라 결과가 같고, OFF 상태 표시를 우선하기 위함이다. 5(화재 등 탈출)를 6(접근위험)보다 위에 둔 것은 탈출 필요성이 접근 충돌 위험보다 크다고 보기 때문이며, 가장 확인이 필요한 항목이다.
