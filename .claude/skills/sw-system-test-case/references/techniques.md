# 테스트 기법 적용 가이드

## 동치 클래스

1. 입력(신호, 파라미터, 상태, 명령)마다 같은 방식으로 처리될 값의 집합을 나눈다.
   - 유효 클래스: 사양이 정상 처리를 정한 범위·값.
   - 무효 클래스: 범위 밖, 사양상 무효값(예: CAN 신호의 invalid/SNA 값), 허용되지 않은 상태에서의 요청.
2. 출력 쪽 클래스도 본다: 서로 다른 출력(경고 OFF / 1단계 / 2단계)을 내는 입력 영역은 각각 클래스다.
3. 케이스 묶기: 유효 클래스는 여러 개를 한 케이스에 묶어도 된다. 무효 클래스는 케이스당 하나 — 두 개를 넣으면 어느 쪽이 거부를 일으켰는지 알 수 없다.

예: `차속 0~250 km/h 유효, 해상도 0.1` → 유효 {0~250}, 무효 {<0}, {>250}, {SNA(0xFFFF)}.

## 경계값 분석

순서가 있는 범위의 경계마다 경계값과 그 바로 바깥값을 시험한다. 간격 δ는 사양의 해상도(신호 분해능, 타이머 틱)를 쓴다. 해상도가 사양에 없으면 가정을 `비고`와 `확인 필요`에 적는다.

- 2값 방식(기본): 하한 `min`, `min-δ`, 상한 `max`, `max+δ`.
- 3값 방식: 경계 안쪽 `min+δ`, `max-δ`도 추가. ASIL C/D이거나 사용자가 요구하면 쓴다.
- 임계값이 있는 기능(“80 km/h 초과 시 경고”)은 임계값 자체가 경계다: `80.0`(경고 없음), `80.1`(경고).
- 시간 조건(“500 ms 이상 지속 시”)도 경계다: `500 ms - 틱`, `500 ms`.
- 입력 범위가 물리적으로 바깥값을 만들 수 없으면(예: unsigned 0 미만) 그 바깥값은 실행 불가능하므로 만들지 않는다. 대신 그 사실을 `비고`에 적는다.

## 페어와이즈 (PICT)

PICT 모델 파일(텍스트, UTF-8) 문법:

```
# 파라미터: 값1, 값2, ...
DriveMode:   ECO, NORMAL, SPORT
Gear:        P, R, N, D
VehicleSpeed: 0, 30, 120
DoorState:   Closed, Open

# 제약: 실행 불가능하거나 사양상 금지된 조합 제거
IF [Gear] = "P" THEN [VehicleSpeed] = 0;
IF [Gear] = "R" THEN [VehicleSpeed] <= 30;
```

- 파라미터 이름과 값은 영문·숫자로 쓴다(한글은 PICT 버전·인코딩에 따라 깨질 수 있다). 엑셀에는 그대로 옮겨지므로 베이시스의 신호 이름을 쓰면 된다.
- 숫자 값은 비교 연산(`<`, `<=`, `>`, `>=`)을 쓸 수 있다. 문자열 값은 큰따옴표로 감싼다.
- 무효값(음수, SNA)은 페어와이즈 모델에 넣지 않는다 — 무효값끼리 조합되면 결과를 판정할 수 없다. 무효값은 동치 클래스 케이스로 따로 시험한다. PICT의 `~` 접두사(음성 값)를 쓰면 한 행에 무효값이 하나만 들어가게 할 수 있다.
- 기본은 2-way(`/o:2`). 안전 관련 상호작용이 3개 파라미터에 걸치면 해당 파라미터만 하위 모델로 3-way를 쓸 수 있다.
- 결과 재현을 위해 `run_pict.py`에 `/r` 없이(결정적 결과) 실행한다.

`run_pict.py`는 PICT 출력(탭 구분)을 행 객체의 배열로 바꿔 저장한다. 각 행을 케이스 하나로 만들고, 그 케이스의 `techniques`에 `페어와이즈`를 넣는다.

## WoW 검증 (엣지 케이스)

일반 기법이 놓치기 쉬운 극단 상황이다. 요구사항별로 아래 질문을 던져 실제로 의미 있는 것만 고른다.

- **동시 극단**: 여러 입력이 동시에 경계값이면?
- **시간 경계**: 상태 전이 직후/직전, 시동 직후 첫 주기, 타이머 만료 바로 그 시점에 입력이 바뀌면?
- **토글·채터링**: 입력이 디바운스 시간 근처 주기로 계속 바뀌면?
- **중단·복귀**: 동작 중 전원 리셋, 통신 메시지 누락 후 복귀, 센서 단선 후 재연결.
- **누적·오버플로**: 카운터·타이머·적산값이 최대값을 넘으면?
- **반복**: 같은 요청을 연속으로 빠르게 반복하면?

사양이 그 상황의 동작을 정하면 일반 케이스, 정하지 않으면 `제안` 케이스 + `확인 필요` 항목으로 만든다. 기법 표기는 `WoW 검증`.

## 비기능 테스트에 쓰는 기법

- 타이밍: 요구 시간의 경계(경계값 분석)와 최악 부하 조건(WoW 검증)에서 측정.
- 강건성·안전 메커니즘: `고장 주입`(신호 단선/단락, 메시지 손실, 값 고착) — 주입 수단을 절차에 명시.
- 자원: 최대 부하 시나리오에서 CPU·메모리·스택 사용률 측정, 기준값을 예상 출력에 명시.
