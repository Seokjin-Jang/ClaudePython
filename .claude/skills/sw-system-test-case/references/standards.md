# 표준 요건 정리 (A-SPICE, ISO 26262 Part 6)

테스트 케이스가 어떤 표준 요건을 충족해야 하는지, 그리고 이 스킬의 각 산출물이 어느 요건의 증거가 되는지 정리한다. 조항·BP 번호는 버전에 따라 달라질 수 있으므로, 사용자가 특정 버전을 언급하면 그 버전을 따른다.

## A-SPICE

| 버전 | 프로세스 | 관련 내용 |
|---|---|---|
| 3.1 | SWE.6 Software Qualification Test | 테스트 전략, 테스트 사양(테스트 케이스), 테스트 케이스 선정, 양방향 추적성, 일관성, 결과 요약 |
| 4.0 | SWE.6 Software Verification | 검증 수단(verification measure) 명세 — 합격 기준, 진입/종료 조건, 기법 포함 / 선정 / 수행 / 일관성과 양방향 추적성 / 결과 요약 |
| 3.1·4.0 | SYS.5 System Qualification Test / System Verification | 시스템 요구사항 기준의 같은 구조. 베이시스가 시스템 요구사항이면 이쪽에 해당 |

심사자가 보는 것과 이 스킬의 대응:

| 심사 관점 | 대응 산출물 |
|---|---|
| 모든 요구사항에 테스트가 있는가 (정방향 추적) | `추적성 매트릭스`, `커버리지 요약` — 스크립트가 100% 미만이면 실패 |
| 모든 테스트가 요구사항에서 왔는가 (역방향 추적) | 각 케이스의 `테스트 베이시스 ID` — 존재하지 않는 ID면 실패 |
| 일관성 (테스트가 요구사항 내용과 맞는가) | `테스트 목적`·`예상 출력값`이 베이시스 원문에서 도출됨. 모호점은 `확인 필요` |
| 합격/불합격 기준 | `예상 출력값`(관측 값·허용오차·시간 조건) |
| 테스트 기법·도출 근거 | `사용한 테스트 기법`, `페어와이즈` 시트(PICT 모델과 결과) |
| 진입 조건 | `사전 조건`, `테스트 환경` |

## ISO 26262-6 (2018) — 11절 Testing of the embedded software

목적: 임베디드 SW가 목표 환경에서 SW 안전 요구사항을 만족함을 보인다. 요점:

- **테스트 환경**: 목표 하드웨어와 가까운 환경(HIL, ECU 네트워크, 차량). 각 케이스의 `테스트 환경`에 적는다.
- **테스트 방법**: 요구사항 기반 테스트(requirements-based test)와 고장 주입 테스트(fault injection test). 고장 주입은 안전 메커니즘·진단 요구사항 검증에 쓰며 보통 `비기능 테스트`(강건성)로 분류한다.
- **테스트 케이스 도출 방법**: 요구사항 분석, 동치 클래스 생성·분석, 경계값 분석, 경험·지식 기반 오류 추정, (필요 시) 기능 의존성 분석, 운용 사용 사례 분석. ASIL이 높을수록 더 강하게 권장된다(경계값·동치 클래스는 ASIL B 이상에서 강하게 권장).
- **요구사항 커버리지**: 테스트가 SW 안전 요구사항을 충분히 덮었는지 보여야 한다.

베이시스에 ASIL이 있으면 `test_basis[].asil`에 넣는다. ASIL C/D 요구사항에는 경계값·동치 클래스 외에 오류 추정·고장 주입 케이스가 있는지 한 번 더 확인한다.

## 이 스킬이 하지 않는 것

- 테스트 실행 결과 기록, 테스트 보고서(요약·통계)는 범위 밖이다. 케이스 사양까지만 만든다.
- 회귀 테스트 선정 전략은 사용자가 요청할 때만 다룬다.
